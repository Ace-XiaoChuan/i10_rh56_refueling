# 清理场景中的两个方向抓取位

当前场景来自用户清理后的 `doc/scene_cleaned.pcd`，共 247,103 点。两个手模型直接复用已经保存的 0°、180° 抓取位，不重新变换或配准；手指显示原来的接近预型。

## 打开查看

双击 `index.html` 用浏览器离线打开，无需启动服务器。下拉菜单可选择 0°、180°、两个方向同时显示或只看清理点云。“完整场景”显示全部范围，“抓取区域”聚焦盖体及手模型附近。拖动旋转、滚轮缩放、右键拖动平移。

网页内嵌全部 247,103 个清理点及两份完整手网格。红色为清理后仍保留的 5,742 个盖体观测点，其余点按 Z 伪彩色显示；0° 手模型为灰色，180° 为青色。颜色用于查看几何，不是相机真实 RGB。

`comparison.png` 是相同取景下的两方向对比图。静态图只抽样显示背景点，网页和 PCD 保留全部清理点，两份手网格也完整保留。

## CloudCompare 文件

- `scene_cleaned.pcd`：用户清理点云的字节一致副本。
- `hand_000.ply`：0° 手模型。
- `hand_180.ply`：180° 手模型。

三个文件都使用相机坐标系、毫米单位，可直接一起打开，无需再移动或配准。分别切换手模型可见性即可比较。

`result.json` 保存来源和两方向位姿：点云、网格为毫米，带有 `position_m` 字段的手根位置及 4×4 位姿矩阵平移保留原候选的米制单位，四元数为 XYZW。原始扫描与历史抓姿结果未改写。

## 数据核对

清理后的点与原始扫描最近距离最大约 0.0000611 mm，为 ASCII 保存精度范围；所有 5,742 个盖体点仍在清理版中。核对表明可沿用原来的坐标系和两方向抓取位。

已逐点检查网页中的清理点坐标和行号，并逐顶点、逐面检查网页中的手模型。手模型副本与原模型摘要一致，没有重新放缩或平移。相关结果保存在 `validation.json`，入口配置为 `config/active_point_cloud_scene.json`。

本次仅完成静态场景叠加，没有增加 10 cm 外退位置，没有执行碰撞检查或连接硬件。网页应用脚本已做 JavaScript 语法检查，浏览器交互尚未在本机自动化测试。
