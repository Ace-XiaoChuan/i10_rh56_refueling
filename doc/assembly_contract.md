# 油箱盖项目：需求、工程计划与进度

本文行数：800行，预期阅读时长：57分钟

本项目采用双臂：左臂安装相机，负责观察油箱口；右臂负责抓握、旋拧、完全取下油箱盖并持续持住。两臂由中间的 T 型架固定。当前旋拧仿真采用 AUBO i10 和 RH56DFX 右手，先完成仿真，再接真机。

本文维护当前需求、参数、工程计划和开发进度。具体操作见各工具说明；实验数据保存在 `artifacts/`。

## 任务要求

| 项目 | 约定 |
| --- | --- |
| 初始状态 | 油箱门已打开，盖体初始松紧程度对执行器未知；仿真通过初始剩余啮合行程设置工况 |
| 完成状态 | 盖体完全脱离油箱口，由手持续持住 |
| 设备分工 | 左臂携带相机，右臂负责旋拧，两臂由中间的 T 型架固定 |
| 旋拧臂模型装配链 | AUBO i10 → 传感器 → adapter → RH56DFX 右手；实际右臂安装和工具变换仍需核对 |
| 双臂动作顺序 | 左臂移到油箱口正前方，停稳采集后让位；确认左臂让位并停稳，再由右臂接近和旋拧 |
| 动作分工 | 每段内保持经验证的抓握，由机械臂旋转；不强制固定三指组合 |
| 旋松方向 | 从手侧正对盖体看，逆时针；盖体系外向 +Z 的正转角 |
| 参考转角 | 最紧状态下约 225°（0.625 圈）；螺纹退出啮合后还需轴向拔出，实际阶段切换由反馈决定 |
| 重新抓握 | 一段结束后，确认机构仍可靠支撑盖体，才松手、退开、重新观察和抓握 |
| 失败处理 | 停止并等待人工，保持已有抓握，不自动重试或释放 |
| 当前范围 | 旋松、取下、持盖；不做装回、放置、开关门或加油，全程无液体 |

盖体松手后不会自行回转，这是用户提供的机构说明。轴向支撑状态仍需要执行反馈确认。

## 双臂分工与坐标传递

用户确认，原有两批 AUBO 资料来自左侧拍照臂的控制盒。该控制盒地址为 `192.168.1.32`；已有 DH、负载、重力、TCP、力传感器读数和状态验证均属于左臂。近期相机配对观测和状态桥联机记录也使用此地址，不能作为右臂参数或右臂反馈。

用户于 2026 年 11 月 2 日确认 `192.168.1.253` 为右臂控制盒；左臂为 `192.168.1.32`。两台均返回 `aubo_i10_JY`、`rob1`、非仿真模式。右臂 TCP 偏移为 `[0.004, 0.0153, 0.5038, 0, 0, -0.044]`（平移 m、姿态保留 SDK 原值）；左臂 TCP 偏移为零。历史发现记录见[双臂设备发现记录](../artifacts/hardware/aubo_dual_arm_discovery_20261026T073239Z/README.md)，其中右臂 `PowerOff` 为当时状态；本次只读查询右臂为 `Running`、`Normal` 且静止。两台的 `rob1` 和 RTDE `R1` 都是各控制盒内部标识，设备侧别按控制盒 IP 绑定。

左臂的相机到法兰标定继续使用。用户已提供并确认左臂基座在右臂基座中的六维位姿、姿态约定及基座原点与安装面的对应，见[双臂与 T 型架安装参数](#双臂与-t-型架安装参数)。该位姿定义 `right_base_from_left_base`，将左臂基座坐标转换到右臂基座。T 型架用于固定相对安装，模型装配参数与实物精度复核分别记录。

统一以 `A_from_B` 表示将 B 系坐标映射到 A 系。双臂观测传递为：

```text
left_base_from_cap = left_base_from_left_flange_at_capture @ left_flange_from_camera @ camera_from_cap
right_base_from_cap = right_base_from_left_base @ left_base_from_cap
```

其中左臂法兰位姿必须使用采集时的记录。左臂让位后，只要盖体、场景和双臂安装保持不变，就可继续使用该次观测；不能改用让位后的左臂法兰位姿重新解释旧点云。观测文件中的 `base_from_flange` 和基座系候选仍指左臂基座；双臂场景生成器已沿安装链将候选和地图一起转换到规划世界系。

流程按顺序交接：右臂保持等待 → 左臂到观察位并停稳采集 → 保存观测与左臂位姿 → 左臂让位并确认停稳 → 使用右臂自身实时状态规划接近 → 右臂抓握、旋拧、取下并持盖。需要重新观察时，由任务层先安排两臂姿态再采集。观察位、让位位姿和路径仍需确定；规划场景要覆盖另一机械臂、相机、T 型架及现场障碍。

双臂与 T 型架模型已接入实测 MTC，安装查看器见[双臂和 T 型架查看](../src/i10_rh56_moveit_config/README.md#双臂和-t-型架查看)，实际规划场景与轨迹使用[RViz 入口](point_cloud_voxelization.md#实测场景接入-mtc)。现有单臂仿真和规划工具继续用于旋拧算法验证。接真机前需分别绑定两臂控制盒、模型和状态来源，补齐右臂配置、工具安装复核、相机几何及让位交接反馈。

## 当前优先：人工点云与裸法兰规划

右臂当前为裸法兰，没有安装 RH56、外接传感器或转接板。现场接近使用独立裸法兰入口，完成盖体几何估计、双臂坐标转换、无接触规划与 RViz 预览；裸法兰不能执行手根抓姿或手指控制。

RH56 是必须保留的条件。当前离线验证优先人工确认握梁顶面中心、握梁长轴和朝外法向，复用已有固定相对抓姿与 650 接近预型，先检查真实场景中的适用性；本阶段不要求完全自动定位。标注允许人工修正，原点与坐标不能混用内部模型中心；保留 0°/180° 两方向检查。操作与结果见[人工参考与固定抓姿](manual_cap_reference.md)。现有 SpaHybGen 接口和实验保留为对照；用户确认双侧占据后已授权阈值0.1的一批离线候选，设置见本文“几何规划与局部实验设置”。任务程序默认生成入口尚未切换。

当前已把用户以前确认的整手相对抓姿复用到634610点的多视角场景，完成[一组静态参考抓姿](../tools/artifacts/cap_single_reference_20261111_001/index.html)。手根微移0.85mm、转动0.45°后，拇指/食指/中指到单列人工假设侧面的距离为0.96/0.96/0.69mm，朝向偏差18.54°/0.58°/1.48°；完整实测场景、自碰及已接受假设面均无超出0.1mm容差的侵入。结果已独立复核，修正另存，原固定抓姿配置只读。原650预张开构型仍有轻微环境侵入，当前下一步是检查并修正接近与闭合过程，再验证接触和抓稳。

此前单次采集的初始六点标注已获用户确认，原始点号、顶面中心、三轴与相对抓姿另存[确认版本与接近复核](../tools/artifacts/cap_manual_reference_confirmed_001/index.html)。该旧场景中0°抓姿从外退0.100m接近的101个位置未检出原始点侵入，1mm表面格的末端预警经0.25mm运动加密后排除；这不是当前多视角场景的接近结果。旧采集未配对机器人状态，只在原生相机系表达。

本模式使用独立的 `dual_arm_bare_flange` 模型，右臂链末端为 `wrist3_Link`；左臂、已有左臂工具、T 型架和观测环境继续参与碰撞检查。法兰目标由用户显式提供的 `cap_from_flange` 定义，平移为米，旋转为固定轴 XYZ RPY 弧度；预接近位沿盖体外向 +Z 再外退指定距离。法兰不能直接使用 RH56 的手根目标，也不套用控制柜保存的历史 TCP 偏移。当前模式只生成几何路径，实际抓握、轨迹时间参数化和真机轨迹执行仍需后续接入。

输入点云保持 SDK 原生相机系与毫米单位，裁出的整盖必须是同一次采集的原始子集，并携带采集时的左臂前后状态和外参。环境使用同次采集的完整场景或人工清理后的子集，不只加载盖体。抓姿准备的几何表面体素、网络输入与优化坐标间距统一为 **0.001 m（1 mm）**；几何表面按原始观测点保存稀疏占据格，未观测格保持未知。局部网络范围与预训练尺度适配见[油箱盖离线迁移](#油箱盖离线迁移)，历史规划场景不改写。路径复核沿用关节 0.002 rad、几何估计位移 0.001 m。右臂起点和法兰相对盖体位姿每次显式输入，不能将左臂拍照状态作为右臂起点。

## 螺纹运动与拔出参数

盖体采用螺纹连接，旋松后仍需沿盖轴向外拔出。当前先采用用户指定的轴向随动占位值：

| 项目 | 当前约定 | 来源与用途 |
| --- | --- | --- |
| 旋转—轴向关系 | 旋松方向每转 90°，沿盖体外向 +Z 移动 1 mm | 用户指定的仿真假设 |
| 等效导程 | 4 mm/圈，即 `thread_lead_m_per_turn=0.004` m/圈 | 由上述关系换算，实物导程仍待核对 |
| 旋拧阶段轴向增量 | `delta_z_m = 0.004 * delta_angle_deg / 360` | 在螺纹啮合阶段使用，角度与位移采用同一参考起点 |
| 最紧标称啮合行程 | 2.5 mm，即 0.0025 m，对应占位导程下继续旋松 225° | 用户接受的仿真假设，实物仍待核对 |
| 初始剩余啮合行程 | `e0_m` 在 `[0, 0.0025]` m 内，场景初始化时设置 | 最紧取上限，较松取更小值；0 表示螺纹已脱开但盖体尚未拔出 |
| 旋松后的动作 | 保持抓握，沿盖轴向外拔出，再确认已离开开口 | 用户确认的工序 |
| 拔出距离 | 从螺纹脱开并停稳时的位置，沿盖体外向 +Z 再移动 0.100 m | 用户指定的仿真占位值；不含此前啮合阶段的轴向位移 |

较松初态按剩余啮合行程计算，不要求每次从首次抓稳起点旋转 225°。啮合阶段的仿真关系为：

```text
e_remaining_m = max(0, e0_m - 0.004 * delta_cap_angle_deg / 360)
remaining_rotation_deg = 360 * e0_m / 0.004
```

`delta_cap_angle_deg` 为相对场景初始化时刻的累计实际盖角，与 `e0_m` 使用同一参考起点；模型余量跨重新抓握连续保留。任务接口的 `MotionProgress` 另以首次抓稳为参考，接近或闭合期间若盖体已运动，需保留两者的参考偏置。模型依据盖体实际运动消耗啮合余量，余量归零时解除螺纹耦合；0 初态从开始即无螺纹耦合。初始化较松场景时，盖体相对最紧基准的轴向位置和绕轴朝向也按导程一致地设置。

| 初始工况示例 | 初始剩余啮合行程 | 继续旋松到螺纹脱开所需转角 |
| --- | --- | --- |
| 最紧 | 2.5 mm | 225° |
| 较松示例 | 1.0 mm | 90° |
| 接近脱开示例 | 0.5 mm | 45° |

场景中的 `e0_m` 用于模型初始化与独立评价，执行器不要求预先知道它。当前 E5 使用明确标注的模型状态反馈切换阶段，真实观测与力反馈判据在后续接触与真机阶段实现。

螺纹退出啮合后，保持抓握并按上述拔出距离完成轴向退出。该拔出距离与重新抓握前手部外退的 0.100 m 分属两段动作，参数分别管理。螺纹脱开后尚未拔出时的支撑状态继续待核对。

E3 仿真后端接入时显式配置上述占位导程、最紧标称行程、场景初态及拔出距离；通用 `TaskParameters` 的未知物理参数默认值继续保持 `None`，由调用方区分仿真假设与实物参数。当前预览模型仍只有旋转自由度，轴向耦合与拔出执行尚待实现。

## 当前进度

当前实测 MTC 默认使用 `dual_arm/robot.urdf`、`robot.srdf` 和对应 KDL 配置，右臂用 `arm` 组，左臂及 T 型架参与整机碰撞。地图与候选一起按 `world_from_right_base @ right_base_from_left_base @ left_base_from_camera_at_capture` 转入双臂世界系，不复用单臂临时对齐。当前采用 10 月 28 日装回油枪后的过滤点云，盖体参考中心约为 `[-0.3105028,-1.1251944,0.8576473]` m。右臂默认起点见[右臂初始关节角](#右臂初始关节角)；左臂固定为该次采集前记录的 `[1.09037213774,-0.710088017536,2.12567985878,-1.1991929404,-0.953951769865,-1.18109972982]` rad，尚未指定让位姿态。新场景与结果在 [28 日点云离线更新](../artifacts/perception/observed_scene_update_20261029_001/README.md)，两个方向均完成仅到预抓取位的规划和核对。原 26 日场景及完整接近结果保留为历史基线，其结论不用于新场景。左臂全路径保持不动，模型 FK 与采集法兰位姿一致；这用于核对坐标与关节顺序，不代表实物定位精度。相机、油枪及安装件外形仍待用户提供，本阶段仅离线验证。

实测 MTC 使用 `config/active_point_cloud_scene.json` 的 `collision_scene.mtc_manifest`，当前与 `config/point_cloud_scene_20261028.json` 一致；`source_split_manifest` 绑定新观测的相机系拆分数据，`single_arm_mtc_manifest` 保留旧单臂基线。环境 OctoMap 和独立 `fuel_cap` 在同一份 PlanningScene 中替换旧油箱、门板、盖体，保留地面与完整模型。预抓取外退距离为 0.100 m，手采用 650 预型。路径复核限制关节插值步长 0.002 rad、相邻状态几何估计位移 0.001 m，并检查全模型；这是加密离散检查，不是连续碰撞证明。仅保留原安装接口及架子与地面的固定支撑接触例外；右臂与左臂、架子、盖体和环境的碰撞均正常检查。模型、场景摘要和坐标类型绑定，拒绝将双臂世界坐标用于旧单臂模型。碰撞对照、规划和 RViz 共用加载函数，原单臂归档与入口保留。

RViz 双臂查看采用 20 帧/秒，默认启用 `Move Camera` 工具和轨迹循环播放：左键拖动旋转、鼠标中键拖动平移、滚轮缩放。静态完整场景在新查看器连接时发送一次，避免反复重建全部占据格和盖体 box；这也兼容 RViz 的 volatile 订阅。轻量轨迹消息在有订阅者时每 5 秒补发，切换显示后可继续收到；场景服务在发布时段内继续响应。

接近规划通过 `approach.launch.py stop_at:=pregrasp` 选择仅到预抓取位：终点仍为抓取位沿盖轴外退 0.100 m 的手根位姿，只规划 `move to pregrasp`，不添加 `axial approach`。默认 `stop_at:=grasp` 保留完整接近。两种模式均检查整条路径的全模型碰撞、限位和各自终点；预抓取结果标记为 `mtc_geometric_pregrasp_not_execution`，由同一个实测 RViz 入口回放，不作为已到抓取位的结果。两种模式当前都只生成几何路径；时间参数、真机执行和到位停止反馈仍待接入。

| 执行 | 阶段请求与运动方案 | 驱动臂手，读取运动、抓持、力、支撑和脱离反馈 |
| 任务流程 | 观测与阶段回执 | 调用各模块，管理进度与分支，处理停止 |

任务层不发送关节命令。MTC 负责无接触运动，局部执行层负责机构阶段动作；后续接触控制沿用这一分工。同一组关节同时只有一个控制方，切换时先停稳并确认交接。

方法和数据流见[技术路线](current_technical_route.md)。

## 旋拧与重新抓握流程

1. 获取整盖及周边的同次观测，生成 1 mm 几何体素和网络输入，进行接触预测、RH56 优化与几何筛选。取得独立盖轴后规划并执行接近；握梁坐标不作为生成前置条件。
2. 停稳并交接控制，闭合手指，确认抓稳。
3. 在固定手盖关系下沿盖轴旋拧，按[占位导程](#螺纹运动与拔出参数)轴向随动，读取模型运动、抓握连接和螺纹状态。
4. 确认螺纹退出啮合后结束旋拧并停稳，保持抓握，从当前位置沿轴向外拔出 0.100 m，确认离开开口后持续持盖。
5. 若到达本段旋转边界仍未脱离，停稳后检查支撑。允许释放时，松手并沿盖轴外向退开 0.100 m，重新观测、体素化、预测、优化、筛选，再调整和抓握，继续旋拧。
6. 反馈未知、矛盾或失败时停止，等待人工。

累计进度记录盖体相对首次抓稳起点的实际运动，跨重新观测保留。朝向展开及握梁的 180° 对称歧义由观测提供方处理。

### 支撑检查

当前简化版本读取模型的机构支撑状态，只有明确允许释放才进行重新抓握；未知时停止。下面的试拉与载荷卸载方法用于后续接触验证阶段。

停转后手继续抓握，沿轴做受限试拉，再减小主动轴向拉力，观察盖体位移、回弹和手盖滑移。“卸载”只减小主动拉力，手指仍保持抓握。

释放判断要确认盖体在手离开后仍由机构可靠支撑。手仍可能承担盖重，因此卸载后不动只是辅助信息。这个判据需用能解除支撑、允许盖体自由运动的模型验证，重点统计释放后滑落的误判。

当前状态机使用模拟支撑结论；后续试拉载荷、速度、允许位移、观察时长及判定阈值在 E8 确定。

| --- | --- | --- |

| index | 0.067150148 | 1.500000000 |

### 盖体坐标系

抓取与任务位姿统一使用握梁顶面中心 `cap_grip_top_center`：X 沿握梁，Z 朝开口外侧，Y 按右手规则确定。URDF/MJCF 已有该参考帧；内部 `cap_grip_center` 保留原含义，用于模型几何和历史结果解释。当前模型中顶面沿局部 +Z 比内部中心高 8.5 mm；默认手根偏移迁移为 `[-20, 75, 151.5] mm`，朝向和手的实际抓取位置保持一致。新的感知候选直接使用观测顶面；单独握梁顶面定位算法仍待实现，现有整盖拟合暂保留原检查。迁移范围见[顶面参考迁移](cap_top_reference_migration.md)。

位置使用米，四元数顺序为 XYZW。当前单臂旋拧模型的手根是 `base`，机器人基座是 `base_link`，法兰是 `wrist3_Link`；这些名称不区分双臂，真机观测需先按[双臂坐标传递](#双臂分工与坐标传递)转换到所用规划坐标系。`cap_from_hand` 表示手根在盖体系中的位姿：

```text
world_from_hand = world_from_cap @ cap_from_hand
world_from_flange = world_from_hand @ inverse(flange_from_hand)
```

公共入口为 [grasp_targets.py](../src/fuel_cap_task/grasp_targets.py) 中的 `calculate_grasp_targets(cap, cap_from_hand, *, flange_from_hand, world_from_base)`。输入是世界系 `CapEstimate`、候选读取器返回的 `FixedGrasp.cap_from_hand`、法兰到手根的安装变换和基座在世界系中的位姿。输出 `GraspTargets`，保留 `world_from_cap`、世界系手根/法兰目标和基座系手根/法兰目标，矩阵均为 4×4。无效观测或非 `world` 参考系抛出 `TaskFailure`，错误的相对参考系或安装/基座矩阵抛出 `ValueError`；不隐式换轴或修正输入。来源与时间继续随原始 `CapEstimate` 保存。

计算时先将盖体系中的手根偏移旋转到世界系，再加盖体位置：`p_wh = p_wc + R_wc @ p_ch`。基准场景中，顶面系偏移 `(-20, 75, 151.5)` mm 对应世界偏移 `(-75, -151.5, -20)` mm，顶面原点为世界系 `(0, 998.5, 600)` mm，手根目标仍为世界系 `(-75, 847, 580)` mm。安装链满足 `world_from_hand = world_from_flange @ flange_from_hand`，求法兰需在右侧乘安装变换的逆；当前 43.5 mm 安装高度沿法兰局部 Z，不能直接沿世界 Z 扣除。基座系目标使用 `inverse(world_from_base) @ world_from_target`，也不能把 `world` 和 `base_link` 当成同一个坐标系。

当前模型位姿入口为 [MujocoCapEstimator](../src/fuel_cap_task/mujoco_scene.py)：同步调用 `scene.estimator.read()`，异步任务调用 `await scene.estimator.estimate()`。二者读取同一份模型状态，返回 `CapEstimate`；位姿在 `world` 中表达，时间为同一份 `data.time`，来源为 `simulation_ground_truth`，时钟为 `simulation`。非法状态或位姿返回 `valid=False`，消费方先调用 `validate_estimate()` 再计算目标。查看当前场景输出：

```bash
.venv/bin/python tools/read_cap_estimate.py
```

命令在仓库根目录运行。默认场景的初始握梁中心为世界系 `(0, 1.007, 0.6)` m，项目盖体系 +X 沿世界 +Z、+Z 沿世界 -Y。读取更新派生坐标并返回快照，不推进仿真时间；共享场景时由调用方持有场景锁。

查看第 2～4 步的完整数据流及手盖、安装链和基座转换的矩阵残差：

```bash
.venv/bin/python tools/read_grasp_targets.py
```

[查看工具](../tools/read_grasp_targets.py) 读取并检查候选来源，从同一场景快照提取盖体、安装链及基座位姿，再打印中间矩阵。矩阵残差用于核对计算关系；实际到位由 IK 和执行反馈另行判断。

接近目标入口为同模块的 `calculate_approach_targets(targets, *, approach_distance_m)`，输入第 4 步的 `GraspTargets` 和以米为单位的有限正距离。距离由调用方显式配置，不设默认值；查看工具通过 `--distance` 传入，与已有规划请求的距离单位一致。

函数使用盖体外向轴 `axis_world = targets.world_from_cap[:3, 2]`，按 `p_pregrasp = p_grasp + approach_distance_m * axis_world` 同时平移手根与法兰，保持各自朝向及安装关系。返回 `ApproachTargets`，包含距离、世界系外向轴、世界系接近手根位姿 `world_from_pregrasp_hand` 和接近法兰位姿 `world_from_pregrasp_flange`。接近时从该位置沿 `-axis_world` 到达抓取目标。

查看第 5 步输出的示例，距离 0.1 m 仅用于本次数值查看：

```bash
.venv/bin/python tools/read_grasp_targets.py --distance 0.1
```

基准场景中盖体外向轴为世界 `-Y`，因此手根接近位置为世界系 `(-75, 747, 580)` mm。外向轴随盖体朝向更新；绕盖体自身 Z 轴转动不会改变该轴在世界中的方向。

公共适配位于 [grasp_preparation.py](../src/fuel_cap_task/grasp_preparation.py)：`prepare_grasp()` 接收已读取的 `FixedGrasp`、`CapEstimate` 和装配/基座变换，返回一份 `GraspPreparation`。`with_approach(distance_m)` 只增加接近目标，不重新采样；`task_parameters(existing_parameters)` 把相对抓姿、接近预型和闭合目标写入现有 `TaskParameters`，保留旋拧、拔出参数及未知值。

现场补样使用 `tools/capture_rgb.py`，默认保存到 `artifacts/perception/cap_rgb_dataset/<scene>/`。默认回车采一张、输入 `q` 结束；可用 `--count` 限制本次张数、`--interval` 启用定时采样。原尺寸 PNG 按 `<scene>_0001.png` 编号，重复运行同一场景时续号并保留已有图片。每次重新布置背景后更换 `--scene`，后续按场景划分数据；脚本不自动标注或分配训练/验证用途。相机身份和分辨率沿用 `config/point_cloud_capture.json` 指向的原 INI，不另设相机参数。

RGB 补样在一次相机会话内连续取图，只临时调整 RGB 取图所需开关、触发和全幅 ROI，退出时恢复并读回核对。默认沿用设备曝光与增益；`--camera-info` 只查询实际 RGB 自动曝光、曝光值和增益，不取图或改配置。可选 `--rgb-exposure` 指定手动曝光、`--rgb-exposure-scale` 按本次读取的曝光乘倍数，或 `--rgb-auto-exposure` 开启自动曝光，三者互斥。手动曝光期间关闭自动曝光，退出时恢复原模式与原手动值；原模式为自动时，恢复后不要求动态曝光值不变。曝光原始值范围 20～100000 来自官方 `VZNL_RGBConfig.h`；该头文件未注明时间单位，因此 CLI 和记录保留 SDK 原值，不标为微秒。

`--rgb-gain` 可独立指定本次采图增益，也可与曝光选项一起使用。本机相机通过 `VzNL_QueryParamRange(keDeviceParamType_RGBGain)` 返回的原始值范围为 1～255，未确认与倍数或 dB 的换算关系。设置前再次查询设备范围并读取原增益，设置后核对实际值；退出时恢复并核对原增益。未知原值、越界、设置失败或读回不一致时停止，不保存不确定设置的样本。白平衡继续沿用设备设置。

RGB 补样不启动激光检测或点云扫描，不导出 K/T/Map，不运行检测、分割或机械臂操作。`samples.jsonl` 保存场景、编号、主机采集时间、实际尺寸，以及取图前读取的 RGB 曝光设置；这些设置读数不冒充逐帧硬件曝光元数据。`sessions/` 保存当次 SDK 日志及恢复结果。操作见 [RGB 补样](hardware/vizum_rgb_alignment.md#只采集-rgb-训练样本)；曝光对照的实际改善程度仍需现场试拍确认。

RGB 补样默认使用 `single` 模式，在同一相机会话内逐张调用 `VzNL_GetRGBImage`，每张保存后通过 `VzNL_ReleaseImage` 释放图像；回车与定时采样均沿用这条路径。该接口没有外部等待时间参数，`--rgb-frame-timeout` 对它无效。单帧路径已有真机保存记录，也出现过设备超时，连续补样稳定性仍需现场复核。

`--rgb-capture-mode callback` 保留回调接口用于诊断，现有本机真机记录均为等待完整帧超时，延长等待也未解决，因此不作为默认采图方式。此模式调用 `VzNL_StartRGBCapture` / `VzNL_StopRGBCapture`，`--rgb-frame-timeout` 默认 15 s、允许 0.001～60 s。借用像素在回调内复制，停止回调后保存，不调用 `VzNL_ReleaseImage` 释放借用指针。两种方式退出时均恢复并核对设置，失败不自动重试或切换接口。

同一验证集上的检测 bbox mAP 从 0.077 提升到 0.681，AP50/AP75 从 0.120 提升到 0.865。结果反映同场景定位改善。远景正确框最高分约 0.115，而无盖错误框最高分约 0.226，单独降低统一阈值无法同时解决这两张图。

数据打包见[数据说明](cap_training_data.md)，训练操作见[云端训练](cap_dino_cloud_training.md)。

### RGB-D 与三维接口

仿真采集设置：640×480，lookat 世界位置 `(0, 0.86, 0.42)` m，distance 0.65 m，azimuth 90°，elevation −20°。采集保存 RGB、配准深度、内参和 `world_from_optical`；深度为光轴 Z 值。

仿真 RGB-D 点云重建入口为 `tools/reconstruct_cap_point_cloud.py`：读取同份观测的 RGB、光轴 Z 深度和标定，输出相机系与世界系的彩色点云，并保留原图像素索引。相机光学系为 X 向右、Y 向下、Z 向前，长度统一为米；当前入口要求针孔图像已去畸变且 RGB 与深度对齐。网页最多显示 30000 点以便交互，NPZ 和 PLY 保存全部有效点。重建不读取场景几何或 `evaluation_only.npz`；无效深度不补点，无点区域不据此认定为自由空间。操作与计算说明见[RGB-D 点云工具](rgbd_point_cloud.md)。真实伟景相机直接使用 SDK XYZ，再经 SDK 标定和校正 Map 取得 RGB 像素，见[像素对应](#rgb-与点云像素对应)。

### SDK 扫描降噪

统一采集流程在扫描前按相机配置的 `[denoise] global_enabled=1` 调用 `VzNL_EnableGlobalDenoise` 开启全局降噪，并用 `VzNL_IsEnableGlobalDenoise` 读回核对。开关读取、设置或核对失败则停止采集；设置前登记恢复操作，结束或中途失败时恢复原开关并核对。固定的是每次采集时应用该配置，不永久改写其他相机使用方的设置。旧配置未包含该项时保留设备原开关。

| 参数 | 提供值 | 计算使用值 |
| --- | --- | --- |
| X | 66.81574800613885 mm | 0.06681574800613885 m |
| Y | 125.865040163263 mm | 0.125865040163263 m |
| Z | 109.32585323244238 mm | 0.10932585323244238 m |
| Roll | 0.167457449599 rad | 同左 |
| Pitch | -0.000210802337 rad | 同左 |
| Yaw | 3.119940514551 rad | 同左 |

定义 `flange_from_camera` 为相机到法兰的齐次变换。先将 PCD 的毫米坐标转米，再按以下顺序计算；`base_from_flange` 必须来自该次采集时的关节状态或法兰位姿。

```text
p_camera_m = 0.001 * p_pcd_mm
p_flange_m = R_flange_camera * p_camera_m + t_flange_camera_m
base_from_camera = base_from_flange(q_capture) * flange_from_camera
```

这组参数已取得并确认含义，尚未通过本项目的实物精度复核，也没有历史 PCD 对应的 `q_capture`。配置当前用于记录和后续接入，没有自动接到真机执行入口。相机固定安装后若发生拆装或位移，需重新复核。SDK 返回的法兰位姿须与此处标定法兰一致，不能用带工具偏移的 TCP 位姿直接替代。

## 任务接口

代码位于 `src/fuel_cap_task/`，主要类型为：

| 文件/类型 | 内容 |
| --- | --- |
| `interfaces.py` / `CapEstimate` | 位姿、参考系、时间、来源、有效性和可选置信度 |
| `interfaces.py` / `TaskParameters` | 任务参数及选定生成抓姿；旧通道与模型驱动角分开，物理未知参数不补默认值 |
| `GeneratedGrasp` / `SelectedGrasp` | 绝对手根位姿、模型驱动角，以及独立几何检查证据和预抓取位姿 |
| `grasp_pipeline.py` / `GraspPipeline` | observe、voxelize、infer、generate、select；观测与产物摘要逐阶段绑定 |
| `saved_grasp_pipeline.py` | 保存 SDK 观测后端、可取消优化子进程及禁止运动的离线执行器 |
| `execution_contract.py` / `FeedbackContext` | 执行反馈的来源、时间、时钟域、有效性及说明 |
| `MotionProgress` | 相对首次抓稳起点的累计盖角（度）及可选轴向进度（米） |
| `RunLimits` | 最大旋拧段数和总软件等待时间，运行时显式传入 |
| `state_machine.py` | 状态与分支管理 |
| `validation.py` | 观测及阶段回执校验 |

生成抓姿阶段为 `check_ready → observe → voxelize → infer_contacts → generate_grasps → select_grasp → prepare_execution → estimate → approach → grasp → twist`。其中 `estimate` 单独取得旋拧轴，生成分支允许 `cap_axis` 参考：轴上原点、+Z 朝外，X/Y 为连续稳定的绕轴参考，不要求握梁。旧固定分支不传 `grasp_pipeline`，仍严格要求 `cap_grip_top_center`。

脱离后走 `retreat → hold → completed`；段末尚未脱离时走 `check_support`，明确允许释放后走 `release → withdraw → observe`，重新完成体素、预测、优化和筛选。失败、超时或取消走 `stopping → waiting_for_operator`。所有准备阶段使用同一总预算，取消时先回收活动子进程。

`stop_after_preparation="volume"|"candidates"` 可在 `volume_ready` 或 `candidates_ready` 离线结束，不要求旋拧轴，也不执行接近。候选筛选必须明确通过几何检查；真实 SDK 后端暂时拒绝选择未经检查的原始候选。完整执行器还需实现 `prepare_generated_grasp`，核对手根到法兰变换与模型角执行映射后才允许接近。

回执分别确认抓持、脱离、停稳和允许释放；未知使用 `None`。估计四元数范数误差≤1e-6，置信度在 [0,1]，数值为有限实数；时间、来源和时钟域明确。累计进度保持同一参考起点和坐标系。

`thread_released` 用于确认螺纹已退出啮合；取出阶段的 `clear_of_opening` 另行确认盖体已拔出并离开开口。

完整流程演示仍使用 `mock` 合成反馈；默认入口 `tools/run_cap_task.py` 演示生成准备链，`--grasp-source fixed` 显式选择旧分支。真实输入离线执行器不连接硬件，不能确认机器人的停止或持盖。实际后端需在 `check_ready` 检查所需物理参数和控制条件，`stop_and_hold` 停止后续运动并报告已有抓握的保持状态。

- 实物螺纹导程、有效螺纹行程、初始啮合和支撑解除方式；仿真的导程、最紧行程、较松初态范围及拔出距离已按[机构参数](#螺纹运动与拔出参数)确定。
- 盖体和手的重心及惯量、安装件质量惯量、摩擦及实际手部驱动映射；油箱盖与 RH56 的质量已记录，见[实物质量](#实物质量)。
- 轴向拉力、力/力矩限值、旋转与轴向速度、柔顺参数、检测阈值和停止余量。
- 力传感器测量维度、单位、坐标系、采样和读取接口；零偏与负载补偿；控制器停止保持行为。
- 真机取出距离的复核、持盖终态位姿、持稳时间和任务评价指标；仿真取出距离已采用上述占位值。

机械臂自带力传感器已由用户确认，具体左右臂对应仍需核对。已有 `kw_ftsensor` 查询来自左臂，右臂的传感器、它与装配模型 `sensor_link` 的关系及原生力控能力仍需独立核对。阻力和力矩限值暂缓细化，数值保持未知。

## 研究方向

围绕整盖接触生成、接触对齐、完整臂手构型评价和柔顺旋拧开展研究，与手动抓姿基线比较。重点包括传矩裕度、方向可操作度、局部运动空间和误差鲁棒性。
